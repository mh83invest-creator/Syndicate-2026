## Exact source-level control flow
1. load_save_text() sets p_desc[0] to NUL, opens fixed 'save/%02d.gam', reads at most one header segment of GAME_DESC_TEXT_MAX_LEN=20, closes, and substitutes a localised empty-slot name only if p_desc[0] is NUL. It does not validate total record size, read byte count, file contents or campaign identity. Consequently, an apparent populated slot does NOT prove a fully loadable record.
2. load_player() returns silently when LbFileOpen fails, leaving existing in-memory player/country/equipment/research state untouched, which is not the same as a verified failure reported to UI. Once open succeeds, it performs seven unchecked sequential LbFileRead calls. The first reads 20 bytes into 'players' as temporary header storage, then the next read overwrites 'players' with the actual player block. A truncated read may leave any subset of global state modified without an error path or rollback. There is no temporary snapshot of the seven segments, preflight file size, checksum or campaign discriminator in the read path.
3. save_player() snapshots 'creds = players[Network__Slot].Credits', subtracts 10% only when creds>30000, then attempts LbFileOpen in new-file mode. If open fails, it returns false with the credit deduction still applied. If open succeeds, it performs seven writes, ignores every byte count, closes, and returns true regardless of partial writes or close failures. The existing 10% threshold and successful-save rule are legacy gameplay and MUST NOT be silently altered.
4. All three functions build 'save/%02d.gam' using a slot integer with no campaign parameter. The Save/Load UI cannot distinguish Original Campaign, American Revolt, World Domination and multiple Custom Campaigns solely through these APIs. A campaign-namespace design is still an implementation gate, not a completed feature.
5. setup_file_names() registers SyndFXFileNameTransform(), resolving relative paths against GetDirectoryHdd(). GetDirectoryUser() creates save and screenshots directories, but this does not establish a user-directory path for the ordinary native C LbFileOpen path. File resolver testing on Windows remains mandatory before migration.
6. The fixed record length of 28247 bytes is a 32-bit source-derived expectation from MB-AUDIT-3.9; no on-disk binary was examined.

## Failure-case matrix to test in a disposable installation
- Open failure: save must report failure without unexpected repeated credit deduction; legacy successful-save threshold must remain unchanged.
- 0/19/20/28246/28247/28248-byte or corrupt save: enumerate label and attempt loading while asserting that failure cannot partially mutate global state.
- Short writes, full disk, permission denied and close failure: distinguish true successful save from incomplete record and preserve previously valid save.
- Pre-existing Original Campaign save slots: verify unchanged default paths and bytes after introducing any namespaced modes.
- American Revolt: verify historical SAVE/SAVE2 distinction from the actual installed game rather than assuming current C loader already supports it.
- World Domination and multiple Custom Campaigns: define deterministic mode identity and separate save namespace before any on-disk writes.

## Proposed seam (NOT implementation approval)
Separate campaign identity, slot enumeration, validation, load, and commit phases in a future design review. Preserve original slot format and original gameplay credit rule; select mode-specific storage before opening a file. Require explicit error results; on failure avoid partial state updates or irrecoverable file replacement. No new schema, filename mapping or migration is approved by this audit.
