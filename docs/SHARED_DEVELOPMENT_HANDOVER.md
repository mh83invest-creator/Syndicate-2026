## Critical file-path discrepancy (MB-AUDIT-2.4, 2026-11-01)
The actual bflibrary LbFileOpen backend passes relative paths through registered SyndFXFileNameTransform, which prefixes the game-data directory even for `save/NN.gam`. A separate `game_transform_path_full` special-cases saves to GetDirectoryUser(), but is not that registered transform. Thus save locations depend on the call path. Prior assumption that all save paths resolve to the user directory is incorrect. Preserve legacy files, inspect LB_FILENAME_TRANSFORM build settings and test both paths before implementing campaign-specific saves. No engine edits. See MB-AUDIT-2.4.

## MB-AUDIT-2.5 — active filename transform verified in source (2026-11-01)

## Main systems update — Windows save I/O backend and overwrite risks (2026-11-07)

## Main systems audio priority scheduling checkpoint (2026-11-07)
Native C `SetBFSampleStatus` coalesces same-sample queued requests into one pending entry keeping the highest requested strength; `BFSonundUnkn1` scans eligible pending IDs and chooses **at most one** to request playback per invocation. It decrements all scanned pending flags (normally one-shot), so nonwinners expire rather than remaining queued. The scheduler returns before aging pending entries while `SoundActive` or `SoundAble` is false; with a valid bank, a request queued during mute can remain pending until sound resumes, unless separately cleared by level transitions. `BFPlaySample` bypasses this arbitration, and the mixer can decline an otherwise selected request if no sample slot is free. These are **static source conclusions**, not observed audible faults or measured explosion overhead. Report: `docs/audits/2026-11-07-main-sound-priority-queue-mute-lifetime.md` (commit `6ac84b1b84e0ff96902697b5a61cfc68edf8d61d`). No engine change or Windows testing; preserve original soundtrack, priority handling, 16 FPS tactics, v0.7 and cross-workstream boundaries.
