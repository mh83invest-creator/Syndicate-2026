## Audio idle dispatcher and AIL callback catch-up — 2026-11-01
Main audit traced `game_update_full` → `game_handle_sdl_events` → `LbWindowsControl` → registered `sound_update` → `AIL_API_timer`. SDL events (up to 256 per pump) precede idle-handler calls. `AIL_API_timer` services running timers with elapsed-time accounting capped at 100 ms per call and may dispatch several callbacks when periods accumulate. This is source-confirmed scheduling, not measured explosion slowdown. Full report: `docs/audits/2026-11-01-main-audio-idle-dispatch-and-timer-catchup.md`, commit `7669f778dc4b6ee645a2fd847197f0b6ff28a276`. No production edits or gameplay tests. Next: timer callback registrations and bodies.

## Main Systems — OpenAL buffer ownership/error exits (2026-11-01)
Main source inspection of `engine/bfsoundlib/src/drv_oal.c` confirmed a conditional free-pool ownership hazard: after successful `alSourceQueueBuffers`, subsequent OpenAL operation failures may enter an error label that returns the still-submitted buffer ID to the free pool. No failure was reproduced. Free pool assertions and partial free-buffer destruction are additional test gates. See `docs/audits/2026-11-01-main-openal-buffer-ownership-error-exits.md`, commit `783c8f87949bbd647682a19b80fc278be4717a26`. Documentation-only; protected v0.7 baseline, Graphics and Mission Builder unchanged. Next: sequence buffer ownership and init/free ordering; Windows fault-injection outstanding.

## Main Systems — music queue and shutdown ordering (2026-11-01)
Compared `drv_oal.c` music and digital queues plus digital driver teardown. Music queue resets `buf=0` after successful OpenAL submission, unlike the digital queue; that eliminates one specific post-submission error-return ownership path in the music code. Digital source creation return is not locally checked during driver setup. Normal teardown releases timer, non-free sample handles, OpenAL sources and pooled buffers; incomplete failure rollback remains to be verified. Report `docs/audits/2026-11-01-main-music-queue-and-digital-shutdown-order.md`, audit commit `0a8fbe210048b7b177795a0421f3b721d74fbcf4`. Documentation-only; no code or runtime tests; graphics/mission branches untouched.

## Main Systems — OpenAL music initialization and shutdown (2026-11-01)
Inspected `mssxmidi.c`, `drv_oal.c` and `ail.c`. Normal MDI destruction releases sequences, timer, OpenAL sources, pooled buffers and allocations before global AIL teardown. Music init calls OpenAL buffer/source creation without local result checks; a sequence allocation failure has no local matching buffer-free call. These are conditional failure-path concerns, not measured leaks/crashes. Report: `docs/audits/2026-11-01-main-openal-music-initialization-shutdown.md`, commit `79dab3d9decdafc3e34a2f26d94e8a7e5515edb3`. Documentation only; no source or branch changes, no Windows testing. Next: trace all init-failure rollbacks and pool counters.

## Main Systems — OpenAL pool accounting and init failure exits (2026-11-01)
Verified shared free/total OpenAL buffer counters in `drv_oal.c` and digital/music allocation in `mssdig.c` / `mssxmidi.c`. Both initializers ignore the local buffer creation return and some later early exits lack a corresponding local pool-free call. Normal cleanup uses current sample/sequence counts, which may differ from requested buffers after source creation truncation; `OPENAL_free_buffers` decrements counters by its effective delete request and does not locally reset totals on device shutdown. Conditional robustness issues only; no measured leak, crash or slowdown. Report `docs/audits/2026-11-01-main-openal-pool-accounting-init-failures.md`, commit `51d63881655117f932713066557dec5e433bc712`. No source changes or runtime tests; parallel branches untouched. Next: inspect repeated initialization/shutdown reachability and full driver ownership.

## Main Systems — audio restart lifetime / OpenAL pool persistence (2026-11-01)
Directly reviewed `bfaudio.c`, `init_snd.c`, `init_mus.c`, `ail.c`, `drv_oal.c` and `game.c`. `EnsureAILStartup` gates initialization, while state-dependent sound/music cleanup can reset the AIL startup flag and shut down the backend. OpenAL shutdown does not locally reset shared buffer-pool counters; risk depends on unverified in-process restart and partial cleanup reachability. `game_quit` exits the process after cleanup and is not evidence of mission-level restart. Default `MaxSamples=10` is adjusted to `DIG_MIXER_CHANNELS=MaxNumberOfSamples+5` during sound initialization. Findings: `docs/audits/2026-11-01-main-audio-restart-lifecycle-and-counter-persistence.md`, commit `f9c7c7f75fc1267855b4cc05fd4f34b40736995f`. No engine edits or runtime tests; other workstreams untouched.
