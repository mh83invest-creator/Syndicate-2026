## Assembly evidence
Source: engine/src/syndre.sx blob c35e22621a93d1e07c44d40de8867446ff7c64bf.
- LbFileRead_ at 14884-14896 delegates to ac_read and directly returns its result.
- LbFileReadRNC at 14916-14960 opens a file, obtains LbFileLengthRnc, calls LbFileRead_, and calls assembly UnpackM1. It does not inspect the returned read-byte count; decompression error triggers printf but the final return is the saved file handle.
- LbFileLengthRnc at 14964-15041 reads 0x14 (20) bytes at 14990-14995 without inspecting the count, compares header bytes with an RNC signature, and reconstructs the header-declared unpacked length from four bytes at 15005-15017. For a non-RNC signature it uses ac_dos_filelength. Failure to open results in -1. Unlike the common C implementation, this assembly version requests 20 header bytes, not 18.
- Assembly UnpackM1 starts at 62225. At 62236 and 62251-62253, it takes source and destination POINTERS (two pointer arguments); it checks RNC markers, decodes unpacked and packed lengths, and performs conditional overlapping-buffer movement. It is NOT equivalent to the C signature UnpackM1(buffer, bufsize). A shared patch requires ABI and implementation review.
- load_text at 55249-55289 operates on 4000-byte brief_text and places a trailing NUL using LbFileLengthRnc without checking negative/oversized lengths or the return of LbFileReadRNC. Normal retail file lengths have not been inspected.

## Comparison to mainline
The common C gfile.c LbFileLengthRnc requests 18 bytes, also checking only -1, and its LbFileLoadAt ignores nonnegative short reads. Both have absent full-count validation. But the assembly loader and assembly UnpackM1 maintain distinct calling conventions and cannot be presumed interchangeable. Mainline documents: docs/audits/2026-11-01-rnc-short-read-backend-contract.md and docs/audits/2026-11-01-cross-backend-short-read-and-caller-scope.md.

## Implementation gate
Do not modify either loader until actual callers, pointer extents and test assets have been reviewed; preserve protected v0.7 and the classic mission/campaign save contract. Test truncated headers, missing briefings, oversized decoded payload and valid retail data in disposable Windows copies.

## Work and limitations
Performed: direct assembly blob inspection of loader, header parser, read shim and start of decompressor; comparison with established C audit. No build, binary execution, fixture test, source patch, resource modification or saved-game operation.
