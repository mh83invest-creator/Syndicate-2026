## Source basis
engine/src/syndre.sx, blob c35e22621a93d1e07c44d40de8867446ff7c64bf:
- raw, pos and len Huffman destination tables each have 0x80 (128) bytes (lines 85164–85169).
- make_huftable reserves 16 stack bytes and reads an unsigned 5-bit count (62450–62465).
- For each symbol whose length matches the current outer pass, the helper issues two 16-bit STOS writes at 62487 and 62498 (advancing EDI by 4 total), then writes a 16-bit value at 0x3c(EDI) at 62503. This is one additional indexed write per matched symbol.

## Exact arithmetic
Let k be the 1-based ordinal of a symbol processed by the matching path within one invocation of make_huftable, ignoring symbols not matched in earlier passes. The destination pointer starts at table offset 0 and advances 4 bytes for each matched symbol. The indexed 16-bit write after match k therefore covers byte offsets (4*k+60) and (4*k+61) relative to the original table start. The highest byte written is (4*k+61).

IMPORTANT: This corrects a preliminary arithmetic phrasing: for k=15, highest byte is 121; for k=16, highest byte is 125 (still inside allocated 0..127); for k=17, highest byte is 129 (two bytes out of bounds). Consequently, up to 16 matched symbols fit the 128-byte destination table under this modeled write pattern; the **17th** exceeds it. The main two STOS writes for k=17 are earlier in bounds; the indexed write is the first overrun.

The symbol count comes from 5 bits and may represent up to 31. The separate 16-byte scratch space is already exceeded at count 17 (17th byte is offset 16), and destination table overflow is possible for the 17th matching symbol. These are conditional source-level bounds, not proof that valid RNC resources contain 17 symbols or that a runtime failure has occurred.

## Caveats and next verification
- The outer 1..16 code-length pass can process each symbol at most once when code lengths are in the expected domain. Zero-length entries need special consideration; the exact valid RNC constraints are not confirmed here.
- Validate maximum legal symbol counts/code lengths from reference format and retail resources before modifying the decoder.
- In a disposable instrumented build, use known-good RNC resources and controlled synthetic inputs to inspect scratch/table canaries for counts 16, 17, 31 and varying code lengths. Never patch the existing game based solely on this calculation.
- Coordinate with the mainline RNC audit; original campaigns, v0.7 baseline, existing saves and mission timing remain protected.
