# MB-AUDIT-4.1 — Assembly save/load menu return-handling boundary
Date: 2026-11-01 (Australia/Brisbane)
Branch: feature/mission-builder-audit
Status: STATIC SOURCE AUDIT ONLY.
Prior: docs/mission-builder/audits/2026-11-01-mb-audit-4.0-save-failure-transaction.md
Evidence: engine/src/syndre.sx blob c35e22621a93d1e07c44d40de8867446ff7c64bf and branch engine/src/game_data.c.

## Verified assembly call sites
1. syndre.sx at lines 30390–30400 enumerates indices 0..9 via ac_load_save_text for UI descriptions. The main select menu independently enumerates 0..9 at 54574–54583.
2. The load handler func_2725f at 30621–30631 checks savegame_slot < 10, pushes that index, calls ac_load_player at 30627, then writes 1 to its local completion/transition flag at 30628–30630, without inspecting a return status. game_data.c defines void load_player(int slot), returning early on open failure, and performs unchecked segment reads after success. Assembly cannot learn whether the native load actually succeeded through this call contract.
3. The save handler func_27280 at 30634–30646 similarly checks savegame_slot < 10, passes the slot and description buffer, calls ac_save_player at 30643, and unconditionally writes 1 to its local completion/transition flag. Native TbBool save_player(...) returns false if open fails and true after open regardless of write count. The inspected handler does not check that return value in EAX/AL.
4. The handlers jump back to a shared menu route at 30648 onward. The exact downstream visual implications of the flag and displayed error messages have not been established by gameplay testing; the source proves absence of success-gating immediately after these calls, not every possible external UI effect.
5. Neither menu handler passes campaign identity. All native slot calls target the legacy save/%02d.gam namespace described in MB-AUDIT-4.0; no new save silo has been implemented.

## Engineering impact and integration boundary
- A future robust native loader must expose a success/failure contract to its assembly caller or provide a separately reviewed compatible adapter. Merely adding checked reads to a void function would not make the existing menu able to react to a load failure.
- A robust save pathway must check native completion before signalling success, while preserving original successful-save behaviour, 10% credits deduction rule and ten-slot legacy compatibility.
- Campaign-specific mode identity must be selected upstream of slot enumeration and file access. Preserve Original Campaign, American Revolt, World Domination and Custom Campaign save isolation, including distinct custom campaigns, without silently migrating or overwriting existing saves.
- No source change or new ABI is approved by this audit. Plan work on an isolated implementation branch after source and runtime gate review.

## Next audit gates
- Trace what the shared completion flag drives in the assembly menu, distinguish cancellation vs failed load/save, and identify any direct continuation path bypassing the menu.
- Cross-check mainline docs/CAMPAIGN_SAVE_INTEGRATION_CONTRACT.md before implementation.
- For any future patch: compile 32-bit Windows, test full/partial reads/writes, failed file opens and cancelled operations in disposable copies, retain v0.7 rollback.
