## What was actually implemented
1. `engine/src/eg_environment_capture.c/.h` exposes the original game's planar 640×400 environment-map rendering stage as 4-bit indexed pixels, with a reusable 2× edge-aware pixel scaler applied twice for **4× output (2560×1600)**. Captures source and output as uncompressed 24-bit **Windows BMP** images. Uses the actual active `GraphicsPalette` pointer supplied by assembly, converts 6-bit components to 8-bit as in SDL palette code; no commercial assets are written to public source.
2. A guarded call in original `engine/src/syndre.sx` immediately following `set_all_changes` at the full-map redraw site (previous source lines 19340–19348). The code checks `eg_environment_capture_requested`, preserves all 32-bit general registers via `pushal/popal`, passes the **BScreen and GraphicsPalette pointer values** to C, and does no screen writes. One-shot request resets before file generation. The hook does not alter collision/map/agent draw functions. **Other incremental scroll redraw routes are not yet captured by this hook.**
3. `engine/src/main.c` supports **`--eg-capture-environment` / `-G`**, absent by default; `engine/src/Makefile.am` builds the component.
4. `engine/src/eg_environment_capture_test.c` validates four-plane extraction, bit order, nearest/Scale2x uniformity, and the real BMP export path against synthetic 640×400 memory, checking native BMP headers, output size and one-shot reset. It creates and deletes temporary BMPs inside the CI workspace.
5. CI on the EG branch runs new tests via the existing fast 32-bit Windows job and a full native i686 SDL2 build. Windows CI status/links are to be appended once confirmed.

## Important safety and limitations
- This is a **live renderer diagnostic bridge** with user-generated *offline comparison images*, not replacement of gameplay pixels with enhanced assets. It does not yet alter in-game appearance, nor claim the 4× full-map image has correct actor/HUD occlusion.
- The hook assumes BScreen at the completed full-map redraw contains four planar 32,000-byte layers. Original source uses 0x7d00 bytes per plane, and a 0x50-byte row stride. The exact status of other screen overlays at that instant requires a real Windows screenshot/capture comparison.
- The 4× BMP is edge-aware presentation; **not yet 2026-grade environment art**. Further materials and depth-aware rendering need validated map-to-screen projection and composite/occlusion separation.
- One-off BMP writing can interrupt a frame during a diagnostic run. Normal gameplay (without `-G`) does not perform this work.
- Files are written into the process working directory as `EG_environment_original.bmp` (640×400) and `EG_environment_enhanced_4x.bmp` (2560×1600). Existing files with those names will be overwritten; test in a separate folder. The capture flag is never enabled by default.
- Crucial bug caught and corrected before test: `GraphicsPalette` in original assembly is a 32-bit pointer variable; initial code pushed the variable's **address**, not its value. Later commit changed to `push EXPORT_SYMBOL(GraphicsPalette)` for the correct pointer.
- Original source `main`/protected v0.7, working v0.8 user archive and graphics scaler branch are unchanged. No private game resources committed publicly.
