## Requirement
Add a camera edge-scroll speed control accessible in options, adjustable from slow to fast, retaining **exact v0.7 speed as default**, persisting between sessions. No effect on agent movement, simulation timing, sound, or 30 FPS menu pacing. Preserve four-direction and corner scrolling.

## Architecture gates
1. Inspect `engine/src/syndre.sx` around `scroll_map` and callers to determine whether movement uses steps, delay or separate positional increments. Preserve the confirmed camera edge-coordinate normalization.
2. Identify existing in-game options menu and input controls. If the engine does not have a safe reusable slider, implement a self-contained options UI instead of misrepresenting a hidden configuration value as a slider.
3. Persist setting to user-writable local directory; validate or clamp its values; fallback to v0.7 on missing/corrupt preferences.
4. Avoid globally changing `game_update_full` frame rate; mission loop stays at 16 FPS and only the three v0.7 strategic screens use 30 FPS.
5. Add compile-time assertions / runtime tests for default and limits; perform native Windows DLL import check and actual gameplay regression test.

## Source audit results — 14 October 2026
- [Successful source audit run #38502827437](https://github.com/mh83invest-creator/Syndicate-2026/actions/runs/38502827437), artifact `v0.8-scroll-and-options-source-audit`.
- `engine/src/syndre.sx` function `scroll_map` (original address 0x1e400; around line 19352) first normalises input to the four edge positions then maps cursor coordinates and number-pad keys to ten directional values (the previous camera correction).
- `scroll` at original address 0x1e4e0 (around line 19459) changes `player_view_map_x` / `player_view_map_y` by **one tile per update**, with per-direction boundary checks and redraw logic.
- Current edge-scrolling speed therefore depends partly on the frequency of input/frame calls, not merely a configurable number in a global struct.
- **Architectural caution:** Increasing game-wide calls would accelerate simulation. Scaling the tile increment directly could skip essential destination buffering and drawing, and break the camera fix. Introduce a camera-only accumulator/step policy and test edge/corner redrawing rather than patching global FPS.
- Audited entry point provides directional dispatch but does not yet establish a reusable options slider API; UI implementation remains pending.
- Existing camera function is called multiple times in the mission loop; a future per-call accumulator must account for this so default v0.7 speed is identical.
