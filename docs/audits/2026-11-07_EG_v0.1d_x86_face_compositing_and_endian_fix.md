## Actual original x86 renderer source traced
`engine/src/syndre.sx` blob `c35e22621a93d1e07c44d40de8867446ff7c64bf` fetched directly via GitHub blob and verified by source lines, rather than relying only on prior reports.
- **Lines 66362–66392**, `jump_43cdc`: obtains each selected block component pointer from `data_48ad0`; reads source mask as `mov (%ebx),%eax`, then **ANDs** it into each of four destination planar words at offsets 0, 0x7d00, 0xfa00, 0x17700; reads colour component words at offsets +4,+8,+12,+16 and **ORs** them into the corresponding destination planes. Next row begins at source +0x14. Each source row is **five 32-bit words = 20 bytes**, 16 rows = **320 bytes** for the examined component path.
- On x86, `mov (%ebx),%eax` reads **little-endian 32-bit words**. The earlier offline preview and first `eg_environment_face.c` experiment incorrectly used big-endian per-word decoding. The error is in the *experimental preview/expander*, not the protected game renderer. The first tests had the same faulty interpretation; their success did not prove byte order.
- **Lines 71585–71623**: `data_48ad0` holds 36 pointers. **Lines 71638–71738**: assorted map-column selectors +10/+11, 24-byte block descriptors and component offsets +0,+4,+12,+16; the C prototype does not replace this selection or 36-slot compositor.
- **Lines 71385–71425**: `draw_horizontal` maps horizontal positions to 128-column grid entries and branches between original draw paths, including planar video mode. More mapping/draw order proof is needed for a faithful RGBA overlay.
- **Lines 82625–82639**: level loader receives separate `data/mapNN.dat`, `data/col01.dat`, `data/hblk01.dat`; mission map number can differ from one, therefore `map01` is a test dataset, not confirmed first user-tested mission. **Lines 82676–82683**: `level_palettes` repeats indices 1..5, so `hpal01` remains a preview assumption, not a guaranteed mission palette.

## Integration limit and engineering decision
**Do not push 128×64 RGBA face images into original 32×16 four-plane buffers.** Doing so would break layout or discard the enhancement. Exact engine mask and palette behaviour are proven only at the documented AND/OR word level. A correctly placed, scene-specific high-resolution environment pass must be designed with tile-to-screen projection, 36-face layering, palette selection, occlusion, sprite/HUD separation and performance measurements. The new test-only expander is **not linked into the live game binary**.
Next: cross-check face byte-to-screen orientation and corresponding game map / active palette using Windows source capture; identify safe separate environment-only draw hook, then compile and playtest isolated EG build. Avoid speculative overwrite of `hblk01.dat` or global postprocess; no phase-two lighting, character or weapons changes.
