- Reimplemented RNC1 decoding from the repository's documented C decoder behavior. Independent script validated the **packed and unpacked CRC16 and exact decoded length for all 143/143 RNC1 resources** in this archive. This is stronger than the prior 143 packed headers-only check and supersedes previous independent Python decoder trial failures for the newly tested archive. This does not mean the game's native C decoder was executed or compared bit-for-bit.
- Verified `hblk01.dat` decoded to **321,664 bytes**, `map01.dat` to **52,632 bytes**, `hpal01.dat` to **768 bytes**.
- `map01.dat` has a 12-byte header followed by a 12,288-entry little-endian 32-bit relative-offset table starting at file offset 12. All 12,288 relative pointers resolved inside the decoded file to **12-byte column records**; 289 distinct pointer offsets found. These raw offsets were analysed **before** the native engine's runtime pointer rebasing, consistent with the previously audited assembly.
- The map01 column record's two visually relevant candidate selector bytes at +10/+11 contain five block descriptor IDs >4: ID **160** (12 occurrences), **237** (4), **193** (4), **124** (3), **246** (3). Frequencies count field references in the 12,288 map cells, not every visible draw call, and do not establish that map01 is the user's first mission.
- Each selected 24-byte `hblk01.dat` descriptor contains six 32-bit relative offsets, all six nonzero in these five tested descriptors, with 320-byte buffers in bounds. We reconstructed **30 original 32×16 indexed planar face previews** (five 32-bit words per row: one candidate mask plus four colour bitplanes). The mask interpretation is appropriate for **offline diagnostics only**, not an independently proven reconstruction of the game's AND/OR composition and occlusion.
